# 家教筛客

此 Skill 配合完整项目使用。源码：`https://github.com/Caspainnn/Totur-Filter`。用户只提供网址时，负责检查和部署环境、引导填写偏好、运行并交付报告，不把安装清单转交用户自行研究。

## 首次部署

先读 [部署指南](references/deployment.md)。以用户实际项目目录和 Python 为准；若 Skill 被安装到个人技能目录，先定位完整项目，不把 Skill 目录当项目根目录。没有项目时克隆完整仓库。不得带入其他电脑的私人配置、群名、订单、既有授权或计划。

在读取微信前，说明 README 中的账号风险：消息读取涉及进程及数据库，非官方接口，存在账号受限或封禁风险；本地只读不保证安全。许可允许个人寻找有报酬的家教，不允许销售、收费部署、付费托管及机构商业使用；详见根目录 LICENSE。

引导用户填写 [用户偏好模板](assets/用户偏好模板.md)，保存到项目根目录 `用户偏好.md`。未提供项不猜测。本人档案、学科、年级、报价、每周时段、城市与起点、通勤阈值、群白名单必须核实；明确“不限制”与“尚未填写”的差别。仅追问当前阻塞项，其他可独立配置项先处理。

地图必须使用该用户自己的高德 Web 服务 Key。仅通过本机交互录入，绝不要求在聊天、文档或命令行明文粘贴。不得打包作者 Key，不得使用共享 Key，也不得回退到作者账户。现存本机 Key 需要用户确认归其本人，不读取或输出密钥来证明归属。

## 配置依据

- 白名单：`config/chat_allowlist.json`；本人档案：私有 `config/tutor_profile.json`；基础偏好：`config/tutor_preferences.json`。
- 用户要求按文档同步时，读取 `用户偏好.md`，仅应用明确填写内容。日常运行读取当前 JSON 与反馈覆盖，不凭历史对话重建规则。
- `manual_closed_orders.json` 中 `preference_overrides` 优先于基础 JSON；更新同一项时检查并同步覆盖项，保留未涉及的反馈、熄单和其他设置。后台只接受 `src/user_settings.py` 中已支持且合法的覆盖项。
- 不将测试配置当用户默认配置。教学经验不能推断为考试、专业或资格证经验，学校等级未知时保留未知。
- 当前支持年级列表、分学段科目与每日多个时间区间；仍有北京场景的地点和院校规则。新城市或新表达需核对实现与脱敏测试，不能仅改 JSON 就称完全支持。
- 当前本人性别已知时，有针对待确认原文的反向性别关键词规则，学生性别也可能触发；旧开关不能关闭已知性别时的该逻辑。首次配置须告知用户此限制；不符合用户需求时明确说明，不静默承诺已关闭。

## 正式运行

在完整项目根目录运行：

```powershell
& .\scripts\run_once_scheduled.ps1
```

默认使用项目 `.venv\Scripts\python.exe`。用户指定已有环境时传 `-PythonPath`，不得硬编码作者路径。脚本每次调用执行一轮，可重复调度。

核对退出码、`scheduled-once-result.json` 的 `status`、`generated_at`、`counts`、`report`，以及 `map_skipped` / `map_unavailable`。成功后用当前 Python 运行 `-m src.report_server`，将返回的本机 URL 在浏览器中打开并提供链接；该命令复用已启动服务，无服务时隐藏启动。服务只监听127.0.0.1，不读取微信或查询地图。失败不能交付旧报告冒充本轮成功。地图不可用不等于通勤已核实。

用户没有 Key 或明确选择非地图检查时，可用 `-NoMap` 生成降级报告，说明线下通勤未核实。配置好本人的 Key 后恢复正常入口；不能为了制造成功结果静默禁用地图。

流程：拆单与结构化提取 → 代码条件筛选 → 对其他条件已明确的候选查询高德 → 输出原因与报告。不要逐条调用 AI API 重做规则或外传原文。只通过正式入口读取白名单，不使用探针、私聊或扩大白名单排障。

## 时间范围与地图

- 当前首次采集、规则变更重读及本地保留为七天；展示窗口可选过去 1、3、5、7 天，以源消息发布时间为准。后续增量采集，过期数据由成功运行清理。浏览器切换范围只筛选已采集数据，不启动新采集。
- 同编号优先保留最新订单及其来源；多单消息先拆分，每张卡片只保留自己的原文片段。单独编号、回收通知不自动撤销其他订单。
- 地图只接收净化后的地点、坐标、日期和时间，不发送正文、群名、联系人或本人档案。仅通勤未核实的候选按北京时间当日优先、最近发布优先查询，已排除、已熄单及窗口外订单跳过。
- 使用现有日上限、请求间隔和24小时路线缓存，不擅自提高额度或绕过限制。当前默认每日100次请求，包括定位和路线请求，不等于100份订单。
- 纯线上无需地图；混合线上线下不按纯线上放行。站点或地标附近允许参考路线，但标明参考目的地与时段，不当作住宅全程精确路线。
- 无地址、多地点、未匹配、额度、网络、无路线等保留具体原因；不能用笼统“待确认”掩盖程序错误。不要猜住宅或选择任意同名地点。

## 报告与反馈

报告支持待选、熄单、结构化字段反馈、用户设置与亮暗主题。🛒是浏览器待选状态，不等于后台推荐或已接单。仅浏览器标记不会改变后台地图查询。

使用 Agent 启动的本机网页时，点击“保存更改”直接写入当前项目的 `manual_closed_orders.json`，不需要选择目录或文件。接口只接受固定文件及合法字段，读取已有内容合并，并用版本校验拒绝并发覆盖；保存失败不能提示成功。

直接打开磁盘 HTML 仍保留手动文件保存兼容模式，应优先重新启动本机服务并给用户网页链接。不能将下载目录中的文件称为已生效，也不能宣称静态 HTML 可自行启动服务。服务停止后用同一启动命令恢复；不新增开机启动或定时任务。

保存偏好后重新筛选才会重新评价订单（窗口切换属于本地展示）。字段反馈按对应字段匹配，不外推全局阈值；用户确认的熄单编号精确匹配，避免短编号碰撞。保留现有学习规则、反馈与手动状态。

## 定时计划

仅在用户提出计划或明确填表要求时创建。先检查是否已有同项目任务，再通过当前环境支持的自动任务工具更新；不同时增加 Windows 和 Codex 重复计划，不继承作者的任务ID或时间。

记录时区与用户时刻。默认仅新增有意义候选、失败或需用户处理时通知，其余安静。电脑、Codex 和微信须可用，Skill 安装不等于常驻服务。不自动发送微信消息、联系客户或代接单。

## 验证边界

文档与样式改动不触发微信读取或地图请求。逻辑变更使用虚构样例运行：


界面交互变更按 [开发验证](references/deployment.md#离线验证) 运行 Node 测试并做浏览器人工验证。只把实际通过的步骤称为成功；离线测试不等于真实微信或地图已验证。密钥、数据库、原文、私人配置和真实报告不得写入 Skill、Git 或外部 AI。
